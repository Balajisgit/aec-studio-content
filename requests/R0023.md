# R23 · Chat (orchestrator): context assembly, including driving a pipeline run

Build on R13's source list (one list for stages and the chat). Today every reply gets the whole briefing (cut at 30,000 characters, 24 KB and growing), a 500-character label of what is open, the last 30 messages, instructions in the app's code, about 30 tools, Opus; long chats forget, and nothing shows what a reply used.

- agents/chat.json in content: instructions, tier, context lines (changed by pull request).
- Small core every reply: the rules; what is on screen in full (open project's summary, selected element, open run, open Object); runs waiting for the owner; open requests one line each; the pipeline catalogue with a new 'use when' line per pipeline.
- Topic pack chosen by what is open: project (notes, recent log, rooms and placements), Library (the Object, similar ones, origin), run, shared work (recent sessions, decisions). Everything else by tool.
- Long chats: the last ~15 messages in full plus a running summary with the owner's decisions in their words.
- A record line under each reply: the parts, their sizes, the cost.
- Orchestrator: when a message matches a pipeline's 'use when', offer or start it.
- Run mode: while driving a run, the pack switches to the run (steps, what it waits for, findings, cost), the pipeline briefly, the subject, what each agent was given (R17), the owner's comments. A chip 'Driving: <pipeline> · <subject> · at <step>'. The chat is quiet while stages run; decisions are posted by the app (no tokens) with buttons; the owner's words go back as a decision comment to the next stage (R15). Stops are explained from the record (Retry, go on without, send back). When it ends: one line in the chat's summary, back to what is open. Fixes go through the run, not by the chat editing results.

To decide: topic by plain code or a quick-model call; who writes the summary; start pipelines or offer first; record line always or on tap; decisions by buttons and typing; fixes only through the run; one run in focus or a chip per run.
