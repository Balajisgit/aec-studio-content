# R117 · Innowa is Claude with its own tools: no separate workshop; the Studio a harness around Claude's harness (option A)

Owner, 23 Nov 2026, on how Innowa should make new things (a skill, a script, an app operation, a Blender script): "When ever innowa creates something new a skill, a script or even a app operation, it works in its own sandbox same how it works in claude.ai web, even a a blender script too." Then: "No separate workshop. Let's use claudes itself. See we are building everything around the claude capabilities. A harness around the another harness(a claudes one). So innowa is a name change.tats it. It is just claude behind the new name." Then: "Ok. Option as A".

Option A: the Studio starts Claude (Claude Code) for Innowa, as now, with Claude's own tools unlocked. The Studio no longer rebuilds what Claude already does; it gives Claude what only the Studio has (the model's operations, projects, the Library, playbooks, skills and scripts in the content, the shared memory) and keeps the owner's gates. Option B (Claude drives the Studio from claude.ai through the connector) is R81, later.

What stays the Studio's: the tools (the only way into a project or the Library), the owner's gates, checks, ledger and limits, the shared content, and the locked-down runner for merged scripts inside jobs.

Steps:
1. Innowa's chat gets Claude's own tools (shell, write, edit, run code) in a folder of its own per chat or job, kept by Claude Code's own sandbox to that folder, the folders the owner connects and allowed sites. On a hosted Studio it runs on the person's PC through the Helper; with no PC it stays read-only.
2. Skills load as Claude's own skills (the content's SKILL.md, with the description Claude reads).
3. Steps that were sessions on a PC (Blender detail, scene, render; slides from a deck) become steps Innowa works in the chat with its shell and the Blender skills; session stages retire.
4. A new script is written and run by Innowa in its folder the first time; what it gives comes into the job through the Studio's tools; "keep it" proposes it as now.
5. (To decide) Innowa may write and test a new app operation in its folder and send it to the owner as a pull request; usable after his merge and a restart.
