# R115 · Innowa and pipelines from first principles: one mind follows playbooks; jobs, rules, checks, workers, one ledger

Owner, 21-22 Nov 2026: pipelines through the app are slow and narrow, while Claude in the web or desktop app is fast. Asked "Do we need pipelines at all?", "How a typical flow would be in this new method", "Does this need full pipeline manager overhaul?", "What if we need to run the pipeline from the run page?", "from the first principle, how innowa and pipeline could have been designed", then "note it straight away as a request and start with. Creating a office floorplan is the first test."

The design discussed:
- One mind: Innowa does the thinking with the full conversation and project; helpers only for work side by side (a brief each).
- The job: one ask, one place; the chat and the run page are two views of it (run, job and chat become one).
- Playbooks: know-how as data (steps to achieve, checks per step, where the owner decides, workers, limits); Innowa follows them and adapts as the owner steers; firms write their own; a job may use none.
- Rules: the owner's gates written once (nothing into the Library without his go, ask before spending over a limit, approve renders), plus a playbook's own gates; project changes stay undoable steps.
- Checks: code, used by Innowa as tools as it works; a gate will not open while one fails.
- Workers: kernel operations, solvers, scripts, PC and Blender sessions, renders; called, run in the background, report back.
- The ledger: one record per job (messages, tool calls, checks, decisions, costs, files); what is reviewed and replayed.
- Learning: corrections become lessons on the playbook step; replayed briefs measure.
- Run from the run page too: the run makes a chat of its own beside the run page; unattended, Innowa carries on there and stops only at the owner's decisions; a pipeline may keep a step as its old agent (a firm's scheduled run).
- Not an overhaul: run records, checks, decision forms, code stages, solvers, sessions, chains, jobs and scopes carry over; the stage engine and separate agent files shrink.

First test: creating an office floor plan as the first playbook.
