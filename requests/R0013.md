# R13 · Context assembly: each stage declares what its agent sees

Pipeline agents see too narrow a context; the chat does better because it sees the briefing, the conversation, what is open and every tool. Separate what an agent can see (wide) from what it can do (narrow: it still writes only the run's data, R3). Each stage declares its context in content, beside its tools, e.g. "context": ["brief-files", "project-model", "library-similar", "owner-notes", "lessons"]; the app assembles the pack from a fixed list of sources (like checks and code stages), so improving what an agent sees is a content pull request. First and biggest of these. Example: Make in Brief to Library never sees the brief's files, only the Need the reader wrote.
