# R116 · Skills, scripts, tools and dynamic playbooks Innowa assembles, instead of pipelines

Owner, 22 Nov 2026: "Instead of pipelines, lets have only skills, scripts, tools and can we have dynamic playbooks that innowa would assemble? Discuss", then "Agree as u suggested."

The design agreed:
- Skills hold the know-how (the reader's, matcher's, maker's and programme writer's instructions become skills in the content repository). Scripts do the exact work (test fit, solvers, the Library check, Blender detail and render jobs). Tools are the app's operations (edit the draft, write the programme, put an Object, look at the plan).
- A dynamic playbook: for each ask Innowa writes a short plan (the steps, the skill or script for each, what each should produce, where the owner decides). The owner sees and can change it; it runs and is recorded like a run. A plan that worked can be saved as a playbook: a starting plan Innowa may follow or adapt. "Office floor plan" is the first.
- Fixed, in the app, whatever the plan: gates on outputs (nothing reaches a project, the Library or the owner's files without his yes; Innowa works on drafts); checks belong to the thing made (an Object can't be kept unless it passes the Library check; a layout is checked against the programme; a plan against the rules), run by the app when the output is saved; every plan recorded in the ledger (steps, cost, time, sent back).
- Limits: the job limits ($ and hours) apply to every plan, and a plan states its expected steps up front.

The owner's decisions ("Agree as u suggested"):
- Approval: Innowa waits for the owner's OK on a plan that changes the project or the Library; a plan that only reads or drafts starts straight away and is shown as it goes.
- Unattended work (scheduled tasks, jobs left running): only a saved playbook, or a plan the owner approved before leaving. No new plans while nobody is watching.

The owner's vision, 23 Nov 2026: "A free standing scripts, skills, tools. Innowa picks and assembles on the fly as a playbook if a job needs one or picks a old playbooks of that suits." Skills and scripts stand alone in the content (a new one is a file, no app change); tools are the app's own operations, where the gates are kept.

Steps:
1. Gates and checks on outputs in the app (the safety net first). Done (aec-studio#130).
2. A plan tool: Innowa writes the steps; the owner sees and edits them on the run page; it runs on the R115 engine (steps by Innowa, confirm, chat, ledger, lessons). Done (aec-studio#131, aec-studio-content#66).
3. Agents' instructions to skills; solvers and code stages as scripts. Done (aec-studio#132, aec-studio-content#67).
4a. Playbooks: save a plan that worked as a playbook, with a "use when"; Innowa looks at the saved playbooks first and uses one as is, adapts it, or writes a new plan only when none fits.
4b. Scripts of every kind: a content script may give back layouts, a report or findings, or files, and says when to use it; Innowa drafts a new one as a content pull request for the owner to merge; the app's own checks (Library check-up, detail check) move to the content as scripts.
4c. Retire the pipeline editor, the fixed pipelines and the old agent stages once nothing needs them.

Replaces what was left of R115 (Test fit as a step, workers, rules as gates, retiring agent stages).
